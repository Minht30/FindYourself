## 2. Plan: six boxes, one commit each (same protocol as Phases 5 and 6)

Each box: build, test (unit + signed-in live + RLS), commit, log in `DECISIONS.md`, tick the ROADMAP, push at the end. Minh is expected to be away again (all six boxes in one run); ask first if he is around.

1. **Bucket + `music_tracks` + upload.** Migration: private bucket `music` (`file_size_limit` 10 MB, `allowed_mime_types` `audio/mpeg`), storage policies so a user can only write / read / delete under `{user_id}/`, table `music_tracks` per the ERD (`id`, `user_id`, `title`, `artist`, `storage_path`, `duration_seconds`, `mime`, `size_bytes`, `created_at`) with per-command RLS, and a **BEFORE INSERT trigger that enforces 10 rows, 10 MB per file and 50 MB in total** (lock the user's row so two simultaneous uploads cannot both slip under the cap). Upload flow: client checks type / size / count and reads the duration -> server action issues a signed upload URL after checking the quota -> client uploads -> server action `finalizeTrack` **verifies the stored object** (its real size, and the first bytes: an `ID3` tag or an MPEG frame sync, never trust the extension or the client's claim), inserts the row, and **deletes the orphaned object if the insert fails**. Stored name = a generated uuid, never the user's filename; the title defaults to the cleaned filename. Library list with delete (removes the object and the row), rename title / artist. Refusals carry named reasons (`library_full`, `too_big`, `quota_exceeded`, `not_mp3`, `bad_duration`, ...).
2. **Playlists.** `playlists` (`id`, `user_id`, `name`) and `playlist_tracks` (`playlist_id`, `track_id`, `position`), cascade on delete; RLS own-row, and a track added to a playlist must be the caller's own (same check as `focus_sessions` / `tasks`). Create / rename / delete, add / remove tracks, **reorder** (dnd-kit is already installed, or up / down buttons plus keyboard), pure `shuffle` helper (seeded, unit-tested: a permutation, no repeats, stable per seed).
3. **Player engine + mini-player.** One `HTMLAudioElement` (singleton, mounted in the app layout like `MixerProvider` so it survives navigation), routed through the **shared `AudioContext`** (`lib/audio/context.ts`) if that is cheap, otherwise a plain element with its own volume. A pure queue state machine (`lib/music/queue.ts`: play, next, previous, shuffle, repeat off / all / one, jump, remove-while-playing; unit-tested) and a zustand store persisted like `fy-mixer` (`skipHydration`, **never autoplays, never persists `playing`**). **Signed URLs**: the bucket is private, so request a short-lived URL per track (about 1 h) and refresh on `error` / expiry. Media Session API for lock-screen / keyboard media keys. Mini-player: title / artist, play / pause, previous / next, seek bar with `aria-valuetext`, music volume, shuffle / repeat. Mount order: audio never starts before a click. Fill in `mixer_state.current_track_id` (migration: FK to `music_tracks`, `on delete set null`; saved with the mix, restored without autoplay).
4. **Music for focus sessions.** A picker (a playlist, one track, "ambient only", or "none") in Timer settings / on /focus, remembered; when a focus session **starts** (the Start click is the gesture) the chosen music begins, and it pauses or continues on breaks (a setting, default: pause on breaks). Must not fight the chime and must never start by itself on page load. Phase 5's `FocusProvider` and `timer.ts` are the places to hook into; keep the timer state machine pure.
5. **Suggest a track + `track_suggestions`.** Table per the ERD (`suggested_by`, `title`, `artist`, `link`, `reason`, `status` pending / approved / rejected, `reviewed_by`, `created_at`); RLS: insert own (as `authenticated`), select own **or admin**, update admin only. A validated server action: **only `https` links to an allow-list of hosts** (youtube.com, youtu.be, open.spotify.com, spotify.link), length limits on every field, a cap on pending suggestions per user (for example 5) enforced in a trigger, named failure reasons. Thank-you toast / message. Links open with `rel="noopener noreferrer"` in a new tab; **nothing is embedded**, nothing the user typed is rendered as HTML.
6. **Community picks + admin review.** `community_picks` (`id`, `title`, `artist`, `link`, `note`, `suggestion_id` nullable, `sort_order`): readable by every signed-in user, **writable only by an admin** (policy via the `admins` table). A small admin-only review view (pending suggestions -> Approve / Reject; approving sets the status and creates the pick **in one database function** with an admin check inside, so it is atomic). Non-admins never see the admin view and a direct call is refused with a named reason (`not_admin`). The picks list shows for everyone with the link buttons.

## 3. How to test it (headless-friendly)

- **Fixtures without downloading anything:** write a tiny Node script (kept in the scratchpad, not committed) that generates valid silent MP3 files: MPEG-1 Layer III frames, header `FF FB 90 00` (128 kbps, 44.1 kHz) followed by 413 zero bytes per frame (~26 ms each), with and without an `ID3v2` header; plus a text file renamed `.mp3`, a file with the wrong magic bytes, and a >10 MB file for the refusals. Check that Chromium actually decodes them (`audio.duration`).
- **Unit tests (vitest):** quota maths, upload metadata / header-byte validator, filename sanitising, link allow-list (look-alike hosts, `javascript:`, `http:`, userinfo tricks such as `https://youtube.com@evil.com`), queue state machine (every transition, repeat modes, removing the playing track), shuffle, signed-URL refresh logic, validators' named reasons.
- **Live, signed in as the test account (localhost):** upload through the real file chooser; the library shows it; **10 uploads succeed and the 11th is refused with `library_full` (assert the request was sent and the reason)**; a too-big file, a non-mp3 and a total-size overflow are each refused by reason and **leave nothing in storage and no row**; delete removes the object and the row; reorder persists across reload; **play, then navigate across pages: `currentTime` keeps advancing and the same element survives**; seek, next / previous, shuffle, repeat; the URL refresh path (force an expired URL); signed out -> the actions return no result (middleware redirect, see Session 26: assert "not signed in" by reason); hydration after 2-3 loads with a saved queue; nothing plays before the first click; focus-session music starts on Start and pauses on a break; suggestion limits and link rejections by reason; the admin flow end to end (use a second throwaway user or temporarily insert yourself into `admins`, and clean up).
- **RLS in SQL** (`begin ... rollback`-style aborting `DO` block as `authenticated` with real JWT claims, as in Sessions 26 / 36): own rows only on every new table; another user's track cannot be put in my playlist; **storage policies**: cannot read / write / delete under another user's folder, cannot upload a non-mp3 or an 11 MB object, cannot exceed the per-user caps; `anon` has nothing; `community_picks` writes denied to non-admins; `admins` not writable. Run `get_advisors` (security and performance) after each migration.

## 4. Gotchas to remember

- **Windows shell:** apostrophes inside single-quoted `node -e '...'` break the command; multi-line `node -e` string replaces fail on CRLF files. **Use the Write / Edit tools for code and docs**, and `taskkill //F //IM node.exe` to stop a stray dev server. LF -> CRLF git warnings are normal.
- After editing `tailwind.config.ts` or deleting / adding routes, stop `next dev`, `rm -rf .next`, restart. Do not run `next build` while dev is running. One transient Google Fonts failure in a build is fine: rerun.
- Supabase MCP: `apply_migration` creates buckets and policies with plain SQL (`insert into storage.buckets ...`, policies on `storage.objects`); mirror the file under `supabase/migrations/` with the **version the tool reports** (`list_migrations` / `schema_migrations`). Inside one transaction `now()` is constant, so test triggers that depend on it across real requests.
- Playwright MCP: no `require` / `import` in `browser_run_code_unsafe`; read `.env.test.local` through a `file://` page (memory note). File choosers: `page.setInputFiles` on the `<input type=file>`, fixtures from the scratchpad directory.
- Memory rules to keep applying: assert the *actual* failure reason in expected-failure tests (request sent? which reason?); check hydration after 2-3 loads; prefix test data `FYTEST` and delete it at the end; commit messages end with the co-author line.
- The mixer and the timer stay as they are: the chime plays on the shared `AudioContext` and is independent of the mixer; do not break either (their tests are in `lib/audio/` and `lib/focus/`).
